Round 1 test write-up: AI coding agents

How we tested, what we checked, and why each tool lost points. Every scored tool got the same task, the same prompt and the same automated checks.

The task: "Tiny To-Do" (task v1)

Each tool starts in an empty folder and gets this prompt once:

Build a single-page to-do web app in this empty folder using plain HTML, CSS and JavaScript (no frameworks, no build step, no backend). Requirements: (1) add a task with a text input and an Add button, and with the Enter key; (2) ignore empty or whitespace-only input; (3) toggle a task complete (completed tasks are visually struck through); (4) delete a task; (5) show a count of remaining (incomplete) tasks; (6) persist tasks in localStorage so they survive a page reload; (7) escape user text so HTML like <b>x</b> shows as literal text. Entry point must be index.html. Also add a README.md with how to run it.

The tester may only reply "continue" or paste an error. Each reply, or a re-run, counts as one intervention. Time limit: 20 minutes. Each tool used its free tier.

The 10 automated checks

A headless-browser script (Playwright + Chromium) runs these against the tool's output. Before testing, we checked the script against a hand-written reference app, which passed 10/10.

  1. Page loads with no console errors
  2. Add a task with the Add button
  3. Add a task with Enter
  4. Whitespace-only input is ignored
  5. A task can be marked complete (visibly)
  6. The remaining counter shows the right number
  7. A task can be deleted
  8. Tasks and completed state survive a reload
  9. Typed HTML shows as text, not markup
  10. README.md explains how to run it

Checker update (Oct 20, 2026): checker v1.1 fixes a false fail on check 6. When an app shows the number and the word "remaining" as separate side-by-side elements (for example "1 task remaining"), v1.0 read them as two lines and missed the count. v1.1 also reads short counter elements as one line. We re-ran v1.1 on every earlier tool's output and the reference app: all results are unchanged, and a deliberately broken counter still fails.

Each check is worth 4 points (40 total). The other 60 points follow the rubric: quality (25, manual code review), speed & effort (15), cost & free tier (10), developer experience (10).

The model differs between tools and affects the scores. Copilot Free's CLI used its default model, gpt-6-luna. Cursor's CLI used Composer 2.5 (free account default). Aider, Cline, Crush, Goose, Pi and Qwen Code ran on Google's gemini-3.8-flash (free tier). Bolt.new used its Free-plan default model (name not shown). OpenCode used its built-in free model deepseek-v4.1-flash-free (no account needed). A score reflects the tool plus that model.
